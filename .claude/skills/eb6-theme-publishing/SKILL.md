# 테마 퍼블리싱 — less 색상·그래디언트 조정

eXBuilder6 프로젝트의 런타임 테마는 less로 작성되며, 모든 컨트롤(버튼·그리드·입력기 등)의 룩앤필을 결정한다. 이 스킬은 요청된 "느낌"을 팔레트로 설계한 뒤 테마 less 전반에 일관되게 반영하고, 화면을 렌더링한 이미지로 결과를 검수하는 절차다.

## 구조 지도

1. **엔트리 확인**: `clx-src/env.json`의 `runtime-css` 배열이 테마 엔트리다. 경로는 `clx-src` 기준이다(예: `/theme/cleopatra-theme.less` → `clx-src/theme/cleopatra-theme.less`). 항목이 여러 개일 수 있으니 가정하지 말고 매번 읽는다.
2. **엔트리 파일**은 `@import` 목록만 있다. 첫 import인 `settings.part.less`가 전역 설정, 나머지 `controls/*.part.less`(컨트롤별 수십 개)가 컨트롤별 스타일이다. `theme/README.MD`에 스타일링 가이드가 있다.
3. **`theme/settings.part.less`** — 전역 변수: 기본 폰트, 텍스트 색(기본/disabled), 보더 색(기본/포커스/disabled), 아이템형 컨트롤의 hover·selection 전경/배경(+disabled selection). 톤의 뼈대는 여기서 잡힌다.
4. **`theme/controls/*.part.less`** — 변수를 참조하면서도 **하드코딩 값이 다수다**: hex 색, `linear-gradient`(button·slider·progress-bar·grid·treecell 등), `rgba(0,0,0,…)` 그림자, `white`/`black` 키워드, `text-shadow`. **settings 변수만 바꾸면 테마가 절반만 바뀐다** — 하드코딩 값 교체까지가 이 스킬의 본체다.
5. **기본 CSS 계층(`cleopatra.css`)** — 테마는 백지 위에 그려지는 게 아니다. 런타임과 스튜디오 프리뷰 모두 런타임 내장 `cleopatra.css`를 먼저 링크하고 그 뒤에 프로젝트 테마를 링크한다. 최종 화면 = 기본 css 위에 테마를 덮은 결과이며, **테마가 같은 셀렉터·같은 속성을 선언한 곳만 테마가 이긴다.** 나머지는 기본 css 값이 그대로 산다. 자세한 내용은 아래 "기본 CSS 계층" 절과 `base-css-defaults.md`(이 스킬 디렉토리에 동봉).

## 기본 CSS 계층 — 테마가 덮지 않은 것들

테마 파트(`controls/*.part.less`)는 기본 css의 사본이 아니라 **덮어쓰기용 뼈대**다. 기본 css는 850여 개 셀렉터를 선언하지만 테마 템플릿이 실제로 내보내는 셀렉터는 200개 남짓이고, 색·배경·보더·그림자 선언 기준으로 기본 css의 360여 건이 테마 손을 전혀 타지 않은 채 살아 있다. 이 사실을 모르고 테마 파일만 고치면 "고쳤는데 화면이 안 바뀌는" 컨트롤이 반드시 남는다.

알아야 할 성질:

- **주석 줄은 값이 아니라 힌트다.** 테마 파트의 `// background-image: url(icons/checkbox.png);` 같은 주석은 "기본 css에 이런 값이 있다"는 안내일 뿐이고, 실제 값은 기본 css에 있다. 주석은 오래된 스냅샷이라 실제와 다를 수 있다(예: 그리드 필터 다이얼로그 폭이 주석은 300px, 실제 기본은 350px). 주석을 풀어 쓸 때는 값을 그대로 믿지 말고 `base-css-defaults.md`의 표와 대조한다.
- **테마 settings 변수는 기본 css에 닿지 않는다.** 기본 css는 런타임 빌드 시점에 자기 변수(주조 tint `#1F8BF0`/`#1369C5`, 반투명 selection `rgba(32,138,237,.5)`, disabled 배경 `rgba(119,119,119,.5)`)로 이미 컴파일돼 있다. 테마의 `@selection-background`를 바꿔도, 테마 파트가 그 변수를 실제로 내보내는 셀렉터에서만 바뀐다. 대표 사례: 테마 `grid.part.less`의 `.cl-grid-row.cl-selected` 블록은 주석 처리돼 있어서, 그리드 행 선택색은 테마 변수와 무관하게 기본의 반투명 파랑이 그대로 나온다.
- **파트 자체가 없는 영역**: 커스텀 스크롤바(`.cl-vscrollbar`/`.cl-hscrollbar`, 트랙 `#f0f0f0`·썸 `#cdcdcd`), 이미지 영역 stroke, 컨테이너, 폼레이아웃 셰이드·구분선 일부. 이런 곳을 바꾸려면 해당 파트 파일을 새로 만들어 엔트리에 `@import`하거나 가장 가까운 파트에 셀렉터를 추가한다.
- **셀렉터 특이도 함정**: 테마가 뒤에 로드돼도 셀렉터가 기본보다 덜 구체적이면 진다. 확인된 사례 — 메뉴 아이템 hover(테마 셀렉터가 `.cl-menu-list`를 빠뜨려 기본의 `#DAEFFC`가 이김), 그리드 안 입력기 텍스트색(행 상태 셀렉터 `.cl-grid-row.cl-inserted .cl-inputbox` 등이 `#444444`/`#C2C0C0`로 이김). 덮어쓸 때는 **기본 css의 셀렉터를 그대로 복사해** 테마에 적는다. 셀렉터를 새로 지어내지 않는다.
- **아이콘은 PNG다.** 체크박스·라디오·정렬 화살표·달력·닫기·스크롤 화살표 등 기본 아이콘 100장은 전부 PNG라 css로 색을 못 바꾼다. 테마 파트의 `url(icons/...)` 주석을 풀면 경로가 테마 css 위치(`clx-src/theme/icons/`) 기준으로 해석되는데, 프로젝트에는 그 폴더가 없어서 아이콘이 깨진다. 아이콘까지 바꾸려면 PNG를 `clx-src/theme/icons/`에 복사해 재색칠하거나, 다크 테마라면 아이콘 요소에 `filter: invert(1)`류를 얹고 렌더로 확인한다. 어느 쪽도 하지 않으면 밝은 톤 아이콘이 그대로 남는다는 사실을 보고에 적는다.
- **시맨틱 색은 기본 css에만 있는 것이 많다.** 노티파이어 5종(success/info/warning/danger/default), 달력 기념일 `red`, 렌더 오류 `.cl-unavailable`의 `red`, 탭·폼레이아웃 드롭 피드백 `#ff3b30`. 톤에 맞춰 조정하되 의미가 사라지지 않게 한다.

## 작업 순서

### 1. 팔레트 설계

요청된 느낌을 구체적 값으로 먼저 확정하고 한 줄로 보고한 뒤 진행한다. 최소 구성:

- 주조색(primary — 포커스·선택 배경에 쓰임), hover 배경(주조색의 연한 톤), 기본/disabled 텍스트, 기본/disabled 보더, 표면색(버튼·헤더 그래디언트의 밝은·어두운 끝점)
- **팝업·판 표면색**: 콤보 리스트·달력·메뉴·다이얼로그·툴팁·내비게이션·아코디언·페이지인덱서는 기본 css가 흰 배경(`white`/`#fff`)을 깔아두고 있고 테마 파트는 대부분 이를 선언하지 않는다. 배경 톤을 바꾸는 요청이면 이 표면색을 팔레트 항목으로 잡고, 기본 css 흰 배경 50곳 안팎을 덮을 계획을 세운다.
- 다크 테마라면 표면·텍스트 반전과 함께 그림자·`text-shadow`·포커스 링 처리 방침도 정한다(아래 규칙 참고)

### 2. 현황 인벤토리

테마 디렉터리에서 실제 사용 중인 값을 뽑아 팔레트 매핑표(기존 값 → 새 값)를 만든다:

```sh
cd clx-src/theme
grep -rhoE "#[0-9a-fA-F]{3,6}\b" . | sort | uniq -c | sort -rn   # hex 사용 빈도
grep -rn "linear-gradient" controls/                              # 그래디언트 위치
grep -rhoE "rgba?\([^)]*\)" . | sort -u                           # 반투명(그림자 등)
grep -rniE "\b(white|black|gray|grey)\b" controls/                # 색 키워드
```

빈도 상위 값이 사실상의 팔레트다. 같은 값이라도 역할이 다를 수 있으니(예: `#333`이 텍스트에도 보더에도) 교체 전에 등장 맥락을 확인하고, 기계적 전체 치환은 하지 않는다.

**이 grep은 절반이다.** 나머지 절반은 프로젝트 안에 파일로 없는 기본 css에 있다. `base-css-defaults.md`의 컨트롤별 표를 체크리스트로 삼아, 이번 요청의 톤 변경이 닿는 컨트롤마다 "기본 css가 깔아둔 값 중 함께 덮어야 할 것"을 매핑표에 추가한다. 특히 배경 톤·주조색을 바꾸는 요청이면 표의 흰 표면·tint 색·행 상태색 항목은 예외 없이 훑는다.

### 3. 반영

- `settings.part.less` 변수부터 새 팔레트로 수정한다.
- 이어서 컨트롤 파트의 하드코딩 값을 매핑표대로 교체한다. 그래디언트는 **방향·스톱 구조는 유지하고 색만 교체**한다(밝은 끝점→새 표면 밝은색, 어두운 끝점→새 표면 어두운색). "플랫하게" 요청일 때만 그래디언트를 단색 `background-color`로 바꾼다.
- 각 파트 파일의 한국어 주석이 각 값의 역할 설명이다. 주석을 근거로 상태(hover/focus/active/disabled)에 맞는 팔레트 항목을 고른다.
- **기본 css의 짝 속성을 같이 처리한다.** 한 속성만 덮으면 기본 css가 같은 요소에 깔아둔 나머지 속성이 새 값과 충돌한다. 반드시 같이 보는 짝:
  - 버튼: 테마는 `background-image` 그래디언트만 선언하고 `background-color: #E0E1E2`는 기본 css에 있다. 플랫 요청으로 `background-image: none`만 넣으면 기본 회색이 드러난다 → `background-color`를 반드시 명시.
  - 입력기 계열(inputbox·searchinput·textarea·maskeditor·numbereditor·treecell): 기본 css가 `background-image: linear-gradient(#eee, white 3px)` 상단 인셋을 깔아둔다. 테마는 `background-color`만 잡으므로 어둡거나 유색인 배경을 주면 위쪽 3px 밝은 띠가 남는다 → `background-image: none`을 명시.
  - disabled 탭 아이템·페이지인덱서·프로그레스바: 기본 css에 `text-shadow: 0 1px 0 white`가 있고 테마 파트에는 없다. 다크 톤이면 `text-shadow: none`을 해당 셀렉터에 추가.
  - 포커스 링: 체크박스·라디오·그리드 필터 다이얼로그는 기본 `outline: 1px dotted black`, 페이지인덱서는 `outline: 1px solid #4d90fe`. 테마 파트에는 주석으로만 있다. 어두운 배경에서 검정 점선은 보이지 않으므로 주석을 풀어 밝은 색으로 바꾼다.
  - 스피너·화살표 hover: numbereditor·dateinput 증감 버튼, 메뉴·내비게이션 스크롤 화살표는 기본 css가 tint `#1F8BF0`(hover)/`#1369C5`(active)를 하드코딩한다. 주조색을 바꾸면 이 셀렉터들을 테마에 복사해 새 주조색으로 맞춘다.
  - 그리드 행 상태: inserted/modified/editing 배경(반투명 파스텔)과 deleted/nullified 회색, selected 반투명 파랑은 전부 기본 css 값이다. 테마 `grid.part.less`의 해당 블록(빈 블록 또는 주석)을 채워야 바뀐다.
- 기본 css를 덮는 새 선언을 쓸 때는 `base-css-defaults.md`에 적힌 셀렉터를 그대로 사용한다(특이도 함정 회피).

### 4. 검증 — 렌더링 이미지 검수가 주 검증이다

grep은 교체 누락을 잡을 뿐, 결과물이 요청한 느낌인지는 **화면을 눈으로 봐야** 안다. 렌더는 기본 css와 테마를 실제 로드 순서대로 합성해 그리므로, **기본 css 값이 새어 나온 곳은 렌더에서만 보인다.**

- **렌더 검수(필수)**: eb6 도구로 화면을 PNG로 렌더링해 직접 읽는다. 렌더는 스튜디오 디자인 에디터와 동일하게, 런타임 기본 css 위에 프로젝트 테마 less를 얹어 그린다.
  - CLI: `.eb6/cli-tools/eb6-clx-render-design <clx 경로>` / MCP가 연결돼 있으면 `clx_render_design` — 어느 쪽이든 결과는 같다.
  - 산출물은 `<project>/.eb6/render/<이름>.png` — 반드시 이미지를 열어 확인한다. 렌더는 디스크 기준이므로 편집 저장 후 호출한다.
  - **렌더 대상**: `clx-src/ai.gen/`의 생성 지침 화면들(genspec·field-types의 `.clx`)이 있으면 그것들이 컨트롤 카탈로그다 — 최소 버튼·입력기·그리드 세 계열을 덮는 화면을 고른다. 없으면 프로젝트의 대표 업무 화면 몇 개를 고른다.
  - 수정 **전에** 같은 화면을 한 번 렌더해 두면 before/after 비교가 된다(`out_file`로 다른 경로 지정).
  - 검수 관점: 요청한 무드에 부합하는가, 상태 위계(disabled·hover·selection)가 유지되는가, 텍스트 대비가 무너진 곳은 없는가, 구 팔레트 색이 남은 컨트롤이 보이는가, **기본 css 누수**(입력기 위쪽 밝은 띠, 회색 버튼 바탕, 흰 채로 남은 판·팝업, 밝은 톤 그대로인 아이콘·스크롤바, 그리드 헤더의 기본 그래디언트)가 보이는가.
- **렌더로 못 보는 상태는 코드로 대조한다.** 정적 렌더에는 hover·active·focus 상태와 펼쳐진 팝업(콤보 리스트·달력·메뉴·툴팁·다이얼로그)이 나오지 않는다. 이 영역은 `base-css-defaults.md`의 해당 컨트롤 항목을 테마 파트와 나란히 놓고, 기본값이 새 팔레트와 충돌하는 선언이 남아 있는지 하나씩 확인한다.
- **컴파일 확인(보조)**: less 컴파일은 호스트 자동 빌드가 수행하며 산출물은 `clx-build/theme/*.css`다. 저장 후 css mtime 갱신 + 새 색상 grep이면 통과. 갱신이 없으면 호스트 미구동 — 렌더도 불가하므로 "검증 미수행"으로 보고만 한다.
- **교체 누락 점검**: 인벤토리 grep을 다시 돌려 구 팔레트 값 잔존 여부를 확인한다(의도적으로 남긴 값은 보고에 명시). 기본 css에서 의도적으로 안 덮은 항목(예: 아이콘, 시맨틱 색)도 같은 자리에 적는다.

## 규칙

- **색·그래디언트·그림자·보더 색상만 조정한다.** 셀렉터 구조, 레이아웃·크기·패딩, 폰트 크기는 요청이 없는 한 건드리지 않는다. `clx-build/`는 산출물이므로 직접 편집 금지. 기본 css를 덮으려고 셀렉터를 추가하는 것은 허용되지만, 셀렉터는 기본 css의 것을 그대로 옮긴다.
- **상태 위계 유지**: disabled 계열은 항상 저채도·저대비로, hover는 selection보다 약하게. 팔레트를 바꿔도 이 위계가 뒤집히면 안 된다. 기본 css의 행 상태색·disabled 배경을 덮을 때도 같은 위계를 지킨다.
- **가독성 대비 유지**: 텍스트/배경 대비가 무너지는 조합(예: 어두운 배경에 `@default-text-color: #333` 유지)을 만들지 않는다. 기본 css가 하드코딩한 텍스트색(그리드 행 상태 `#444444`, 달력 다른 달 `#a7a6a6`, 플레이스홀더 `#757575`)도 새 배경 위에서 대비를 다시 본다.
- **다크 테마 함정**: `text-shadow: … white`(밝은 배경 전제)는 제거하거나 어두운 색으로 교체하고, `rgba(0,0,0,…)` 그림자는 다크 배경에서 묻히므로 투명도를 높이거나 밝은 림 라이트로 대체한다. 기본 css 쪽의 흰 표면, 입력기 인셋 그래디언트, 검정 점선 포커스 링, PNG 아이콘은 테마 파일에 없어도 화면에 있으니 "기본 CSS 계층" 절의 목록대로 처리한다.
- 오류·경고용 `red` 등 시맨틱 색은 톤 요청과 무관하게 의미가 유지되도록 조정한다(제거 금지).
- **보고에는 두 종류의 잔존을 구분해 적는다**: 의도적으로 남긴 테마 값과, 기본 css라서 못 덮었거나 안 덮은 값(아이콘 등).
