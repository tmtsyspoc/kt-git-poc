# eb6 CLI 사용법

eb6 CLI는 로컬 eXBuilder6 호스트(스튜디오 또는 헤드리스 데몬)의 도구를 셸에서 부르는 브리지다. 프로비저닝이 프로젝트의 `.eb6/cli-tools/`에 단일 바이너리 `eb6`와 명령별 링크 `eb6-<명령>`을 설치한다. PATH 설정은 필요 없다 — 프로젝트 루트 기준 상대 경로로 실행한다.

## 호출 규약

- 프로젝트 루트에서: `.eb6/cli-tools/eb6-<명령> [인자...]` — bash 계열(윈도우 git-bash 포함)은 이 형태 그대로, Windows cmd/PowerShell은 `.eb6\cli-tools\eb6-<명령>`.
- 인자는 `--<이름> <값>` 플래그. 필수 인자는 순서대로 위치 인자로도 줄 수 있다.
- 파일·프로젝트 경로 인자는 상대 경로로 줘도 된다 — CLI가 절대 경로로 정규화해 서버에 넘긴다.
- `--json`을 주면 결과가 JSON 한 덩어리로 나온다.
- exit code: 0=통과, 1=검증 실패·도구 오류, 2=인자 오류, 3=호스트 접속 불가.

## 명령 목록은 라이브로 확인한다

명령 표면(목록·플래그·설명)의 정본은 호스트 매니페스트다 — 여기 목록을 적어 두면 낡는다.

- 전체 명령 목록: `.eb6/cli-tools/eb6 help`
- 개별 명령의 인자: `.eb6/cli-tools/eb6 <명령> --help`

## 갱신

`.eb6/` 산출물(타입 선언·공리·스킬·CLI 자신)이 낡았거나 프로젝트 모듈·UDC가 바뀌었으면 프로비저닝을 다시 실행한다(멱등):

```
.eb6/cli-tools/eb6-provision --project .
```

## 문제 해결

- exit 3(호스트 접속 불가): 스튜디오나 헤드리스 데몬이 꺼져 있다. 기동을 요청한 뒤 `.eb6/cli-tools/eb6 status`로 확인한다.
- `eb6-<명령>` 링크가 없다: `.eb6/cli-tools/eb6 sync`로 재생성하거나 프로비저닝을 다시 실행한다.
- 명령이 출력 없이 즉시 죽거나 바이너리가 사라졌다: 보안 소프트웨어가 격리했을 수 있다. `.eb6/cli-tools/eb6` 존재를 확인하고, 격리됐다면 예외 등록 후 프로비저닝을 다시 실행한다.
- 같은 능력이 MCP 도구로도 올라온다 — MCP가 연결돼 있으면 어느 쪽을 써도 결과는 같다.
