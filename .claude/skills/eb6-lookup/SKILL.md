# 도움말·기술지원 조회 SOP

질문의 성격에 따라 갈래가 다르다. 먼저 어느 갈래인지 정한다.

| 질문 | 명령 | 예 |
| --- | --- | --- |
| 컨트롤의 속성·이벤트·자식 요소, cpr.* API 규격 | `eb6-clx-spec`, `eb6-api-search` | "그리드 셀 편집 이벤트 이름이 뭐지" |
| 오류 메시지, 증상, "안 된다", "이상하다" | `eb6-support` | "컬럼 고정하면 가로 스크롤이 안 움직여요" |
| 스튜디오 기능·개념·설정·절차(공식 사용자 매뉴얼) | `eb6-manual` | "탭 컨트롤은 어떻게 구성하나" |

명령은 프로젝트 루트에서 `.eb6/cli-tools/eb6-<명령>`으로 부른다(사용법은 eb6-cli 스킬). 같은 능력이 MCP 도구(`support_search_cases`·`support_recall_case`·`help_list_toc`·`help_read`)로도 올라온다.

## 1. 기술지원 사례 — eb6-support

```
.eb6/cli-tools/eb6-support "그리드에서 컬럼을 고정하면 가로 스크롤이 움직이지 않습니다"
.eb6/cli-tools/eb6-support --show 162_faq
.eb6/cli-tools/eb6-support --show 162_faq --source true
```

- **질문은 원문 그대로 한 덩어리로 준다.** 키워드로 줄이지 않는다 — 실측상 키워드 나열은 증상 임베딩 공간에서 벗어나 히트가 나빠진다. 사용자의 문장이 있으면 그 문장을 그대로 쓴다. 따옴표를 빼먹어도 CLI가 토큰을 이어 한 질의로 넘긴다.
- 출력은 코퍼스별 섹션(`## [faq]`, `## [qna]`)이고 한 줄이 사례 하나다: `N. (점수) [ID] 제목 | 증상 | 해결 미리보기`. qna 섹션은 컷오프 통과가 신뢰를 뜻하지 않는다는 주의가 붙는다 — `resolutionType`(확정해결·우회책·권고)과 내용으로 직접 판단한다. "저신뢰" 문구가 붙으면 참고만 한다.
- 상세는 `--show <ID>`로 카드 하나씩 본다. 원문 스레드 전문은 `--source true`를 붙였을 때만 나온다(길다 — 카드로 부족할 때만).
- **exit 1 = 근거 없음.** 지어내지 말고 "기술지원 사례에 근거가 없다"고 답하거나, 표현 각도를 바꿔 재검색한다(증상 중심 ↔ 컨트롤·환경 중심 ↔ 정확한 API 이름). 재검색은 두세 번이면 충분하다.
- 사례 코퍼스는 스냅샷이라 최신 버전과 다를 수 있다. 답변에는 근거로 쓴 사례의 ID·제목을 남기고, 해결책을 적용하기 전에 관련 규격을 `eb6-clx-spec`/`eb6-api-search`로 확정한다.

## 2. 공식 도움말 — eb6-manual

```
.eb6/cli-tools/eb6-manual toc
.eb6/cli-tools/eb6-manual toc T-1a
.eb6/cli-tools/eb6-manual read T-2f
```

- `toc`는 `[ID] 제목 (N subs)` 트리다. 인자 없이 부르면 루트 주제 전체, ID를 주면 그 아래만 나온다. 통독하지 말고 루트에서 관심 주제로 좁혀 내려간다.
- `read`는 페이지 하나를 마크다운으로 준다. `#`로 시작하는 제목은 부모 문서 안의 섹션이다.
- **ID는 설치본마다 다르다.** 저장해 두고 재사용하지 말고 매번 목차에서 고른다. 사용자에게는 ID가 아니라 제목으로 안내한다.
- API 레퍼런스는 목차에 없다 — 규격은 `eb6-clx-spec`/`eb6-api-search`로.
- 없는 ID면 exit 1과 "목차부터" 힌트가 온다.

## 3. 예시 동선

- "그리드 컬럼 고정이 안 돼요" → `eb6-support "그리드 컬럼 고정이 안 돼요 ..."`(사용자 문장 그대로) → 히트가 있으면 `--show <ID>` → 해결책을 규격으로 확인한 뒤 적용 → 답변에 사례 ID·제목을 근거로 남긴다. 근거 없음이면 `eb6-manual toc`에서 그리드 관련 주제를 `read`하고, 그래도 없으면 `eb6-clx-spec --type spec --query grid`.
- "탭 컨트롤 사용법 알려줘" → `eb6-manual toc` → 탭 관련 주제 `read` → 요약해 답하고 페이지 제목을 출처로 남긴다.
- "이 화면 저장 버튼 누르면 아무 반응이 없어요" → 먼저 `eb6-support`로 사례를 보고, 화면 자체 문제로 보이면 eb6-implement-screen-logic 스킬의 절차(개요·리스너·검증)로 넘어간다.

## 4. 경계

- 조회 결과는 참고 자료다. 사례 하나로 일반화하지 않고, 적용 전에 규격을 확인한다.
- 근거가 없으면 없다고 말한다 — 사례·도움말·규격 어디에도 없는 내용을 있는 것처럼 답하지 않는다.
